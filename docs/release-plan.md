# Desktop completion, mobile play, and hosting

The current build is the full six-chapter game in desktop beta, with an experimental landscape touch layout. The story has an ending, but a fresh-player continuous run, target playtime, and representative hardware performance still need verification. The 2–4 hour duration in the narrative design is a target, not a measured playtime. Bugs and rough edges may remain during beta.

## Desktop completion gate

- Run fresh-player start-to-finish sessions through the main campaign and each chapter start. Fix blocked routes, bad saves, inaccessible clues, and unclear objectives.
- Expand the short scripted scenes to the intended pacing, then polish environment art, character animation, dialogue delivery, audio balance, and performance without removing the established evidence limits.
- Test common desktop GPU and browser combinations, including rainy and storm chapters, driving and ambient traffic, prison interiors and character placement, wildlife density, high-density grass, and the island coastline. Collect foreground `?perf=1` samples on representative desktop hardware; synthetic CPU timings do not satisfy this gate.

## Firebase Hosting — live desktop beta

The production `dist/` build is live at [https://gamedev-7ac48.web.app/](https://gamedev-7ac48.web.app/) in Firebase project `gamedev-7ac48` (deployed version `67ddef25d129ae81`). The temporary [release-candidate preview channel](https://gamedev-7ac48--release-candidate-1bjth2ik.web.app/) rendered Chapter 1 with no browser warnings or errors. The live site loaded its main menu and Chapter 1 ferry/cliff scene without warnings or errors. This is a public desktop smoke check; the full campaign was verified in an isolated saved browser route, and mobile devices and representative desktop performance remain separate release gates. Preview-channel URLs can expire; share the main live URL.

`firebase.json` serves the production `dist/` directory and `.firebaserc` selects the deployed project. The game uses no Firebase client SDK or backend account. Its progress remains in the visitor's browser `localStorage` for that exact origin; local, preview, and live saves do not synchronize. Future source edits do not update the live site until a new build and deployment.

Hosting transfer and storage count at the project level, including preview-channel traffic. If the project is on the no-cost Spark plan, check its current [Firebase Hosting quota and pricing](https://firebase.google.com/docs/hosting/usage-quotas-pricing) and monitor usage in the Firebase console before sharing this asset-heavy game widely. The ZIPs remain a local-play option if Hosting availability or quotas become a concern.

For later releases, run the source tests and `npm run build`, review a temporary channel with `firebase hosting:channel:deploy release-candidate --project gamedev-7ac48`, then deploy with `firebase deploy --only hosting --project gamedev-7ac48` after reviewing that exact build. The current live deployment does not change automatically when a source ZIP is repackaged. Hosting references: [setup](https://firebase.google.com/docs/hosting/quickstart), [test channels](https://firebase.google.com/docs/hosting/test-preview-deploy), and [configuration](https://firebase.google.com/docs/hosting/full-config).
